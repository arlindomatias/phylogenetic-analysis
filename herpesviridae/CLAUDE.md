# viral_phylogeny

Folder of the private repository `~/github/private` (local path `~/github/private/viral_phylogeny`).
Phylogenetic taxonomy of **Orthoherpesviridae** from NCBI RefSeq genomes, with the five human
herpesviruses linked to cognitive decline in ageing (HSV-1, VZV, HCMV, EBV, HHV-6A) as the
interpretive thread. Follows the conventions of `~/github/proteomics`: a Snakemake workflow chaining
self-contained scripts, parameters in `config/config.yaml`, one conda environment per rule in `env/`,
and a self-contained HTML report built with the shared `scripts/html_report.py`.

## Rules

`download → metadata`, `download → queries → homology → orthologs → align → concat → tree →
taxonomy → plots → report`. Final target: `reports/report.html`.

Run from the project root: `snakemake --cores 6 --use-conda`.

## Conventions

- **Languages:** bash for download and tool invocation, Python for analysis and figures. No R in this
  project. Shared helpers live in `scripts/vphylo.py` (standard library only, so it can be imported
  from the lightweight `markers` environment as well as from `report`).
- **Scripts take explicit CLI arguments** (never the `snakemake` object), so each one can be run by
  hand on its own. Every rule redirects stdout/stderr to `logs/<rule>.log`.
- **`scripts/html_report.py` is a shared file**, byte-identical to the copies in `~/github/proteomics`
  and `~/github/bulk-rna-seq`. Do not edit it here for a project-specific need.
- **`data/` is not versioned** (download + alignments, regenerated by the workflow); `results/`,
  `plots/` and `reports/` are.
- Every number in the report prose is computed from the tables in `results/`, never hard-coded.

## Analysis decisions worth keeping

- **Orthologues come from homology, not annotation text.** RefSeq protein names in this family are
  inconsistent (only 59 of 126 viruses carry a protein named *DNA polymerase catalytic subunit*), so
  the HSV-1 reference proteins in `config.yaml → markers` are DIAMOND blastp queries and the best hit
  per virus is taken, filtered by `homology.min_identity` and `homology.min_query_coverage`. A protein
  that is the best hit of two markers in the same virus is kept only for the higher-scoring one.
- **UL26 (capsid maturation protease) was removed from the marker set**: it is a protease-scaffold
  fusion whose homologues align with the HSV-1 query only over ~36% of its length, so it failed the
  coverage floor in most beta- and gammaherpesviruses. The remaining 8 markers are recovered in
  80–98% of the viruses.
- **Monophyly is tested on bipartitions**, i.e. root-independently, because no outgroup is available:
  *Alloherpesviridae* (fish/amphibian herpesviruses) are too divergent for these alignments. The tree
  is midpoint-rooted for the figure only, and the report says so.
- **Genera with a single sampled virus are reported as "single taxon"**, never counted as monophyletic
  successes — RefSeq samples one genome per virus, so many genera are singletons here.
- The association with cognitive decline is literature context for the highlighted tips
  (`config.yaml → highlight`); the phylogeny does not test it, and the report must keep saying so.

## If the marker set changes

`config.yaml → markers` drives everything downstream (one `align` job per marker, one partition per
marker). Removing a marker only requires deleting its line; stale `data/markers/<marker>.faa` files
should be removed by hand, since Snakemake will not notice them.
